# 1.1 澄清后的目标

1. 一个项目中可以有多个 Git 目录，不能依赖单仓库假设；已登记根之外的项目内仓库也需有界识别。
2. 漏提交配套文件属于跨文件规范问题。框架应按规则提供关联上下文，由 AI 按规则判断，而不是在插件中固化某个登记规则。
3. 问题默认打开当前项目可编辑源码，历史提交内容是另一个可选入口。

## 关联上下文验收

- 任意规则 ID、任意配置文件可通过文字明确引用或 contextFiles 声明进入目标提交上下文。
- 配套文件本次未变更也读取；工作区补改未提交不能掩盖目标提交缺失或旧内容。
- 命名路径变量可以捕获模块、版本；旧整段xxx有通用兼容。
- 歧义、不可读取、预算不足不能被AI标成完整reviewed；预算/批数跳过有覆盖记录。
- 不加入业务规则ID、登记清单文件名、登记编号格式的生产代码特判，不自动改用户规则。

## 导航验收

默认打开报告根内实际项目文件；多根同路径不会串仓库。当前Document用于证据定位，支持未保存内容和项目编码。文件删除、重命名后无法找到或证据已改时明确提示；提交快照不会冒充项目文件。

## 范围

审查仍以已提交快照为准，本轮没有把全部工作区未提交文件自动发送给AI。其他已完成的报告确认、窗口切换、四边吸附及Key状态沿用1.0。关联内容收集是有界、同仓库的，不保证自动发现自然语言未明确描述的所有隐含依赖。
